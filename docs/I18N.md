# Internacionalización (i18n) — Nha Kinhon

Contrato compartido entre **web** (`stuffsergio/nha-kinhon`), **API** (este repo, `backend/`) y **móvil** ([`stuffsergio/nha-kinhon-mobile`](https://github.com/stuffsergio/nha-kinhon-mobile)).

## Idiomas soportados

| Código | Idioma | Notas |
|--------|--------|--------|
| `es` | Español | **Por defecto** (texto histórico de la app) |
| `pt` | Português | Portugués europeu / Guinea-Bissau |
| `pov` | Kriol (crioulo) | ISO 639-3 `pov`; traducción **pendiente de revisión por hablante nativo** |

### Cadena de fallback (web y API)

- `es` → `es`
- `pt` → `pt` → `es`
- `pov` → `pov` → `pt` → `es`

## Campo `User.locale` (API)

- **Prisma:** `User.locale` (`String?`, nullable).
- **Valores permitidos:** `es`, `pt`, `pov` (allowlist).
- **Migración:** `20261010180000_user_locale`.
- **Lectura:** incluido en `GET /api/auth/me`, login y registro (`user.locale`).
- **Escritura:** `PUT /api/auth/me` con body `{ "locale": "pt" }` o `"locale": null` para volver a detección automática.
- **JWT:** el access token incluye `locale` (nullable) para resolver idioma sin consulta extra en cada petición autenticada.

## Resolución de idioma en la API

Orden de prioridad:

1. Usuario autenticado: `locale` del JWT / cuenta (`User.locale`).
2. Cabecera **`Accept-Language`** (primera etiqueta soportada).
3. **`es`**.

Middleware global: `localeMiddleware` (`backend/src/middleware/locale.js`). Las respuestas de error y mensajes de éxito traducibles usan `req.locale`.

### Errores HTTP (contrato estable)

Las respuestas de error siguen incluyendo `error` (texto humano traducido) y, cuando aplica, **`code`** (identificador estable para que el cliente traduzca por código si lo prefiere):

```json
{
  "error": "Credenciales incorrectas",
  "code": "CREDENTIALS_INVALID"
}
```

Los códigos viven en `backend/src/i18n/locales/*.js` bajo la clave `errors.*`. Catálogo principal en `backend/src/i18n/locales/es.js`.

### Mensajes de éxito traducibles

Algunos endpoints devuelven `message` + `code` (p. ej. `LOGOUT_OK`, `PASSWORD_UPDATED`, `FAVORITE_ADDED`). Claves bajo `messages.*` en el catálogo del backend.

## Notificaciones (in-app y push)

Las notificaciones se **persisten ya traducidas** según el `User.locale` del destinatario al crearlas.

Plantillas en `notifications.<TEMPLATE>.title` / `notifications.<TEMPLATE>.message` (backend i18n).

| `type` (Notification) | Plantilla (`template`) | Parámetros |
|----------------------|------------------------|------------|
| `ORDER_CONFIRMED` (pago) | `ORDER_PAYMENT_CONFIRMED` | `shortId` |
| `ORDER_PICKED_UP` | `ORDER_PICKED_UP` o `ORDER_PICKED_UP_ADMIN` | `shortId` |
| `ORDER_IN_TRANSIT` | `ORDER_IN_TRANSIT` | `shortId` |
| `ORDER_DELIVERED` | `ORDER_DELIVERED` | `shortId` |
| `ORDER_COURIER_NEARBY` | `ORDER_COURIER_NEARBY` | `shortId` |
| `ORDER_CANCELLED` | `ORDER_CANCELLED` | `shortId` |
| `ORDER_CONFIRMED` / `ORDER_CANCELLED` (admin status) | `ORDER_CONFIRMED` / `ORDER_CANCELLED` | `shortId` |

Deep links (sin cambios): `orderId`, `screen: "order_tracking"`, `route`, `url` — ver `notificationDeepLinkFields` en `notification.service.js`.

## Recibo / `shareText`

`GET /api/orders/:id/receipt` devuelve `shareText` traducido según `req.locale`. Claves bajo `receipt.*` y `orderStatus.*` en backend i18n. Importes FCFA formateados con `Intl` (`es-ES`, `pt-PT`, `pt-GW` para `pov`).

## Email

`email.service.js` sigue siendo stub (SMTP no configurado). Cuando se integre nodemailer, los asuntos/cuerpos deben usar el mismo catálogo i18n y el `locale` del destinatario.

## Web (React + react-i18next)

- Config: `src/i18n/config.js`
- Recursos: `src/i18n/locales/{es,pt,pov}.json`
- Persistencia local: `localStorage` clave **`nha_kinhon_locale`**
- Detección inicial: `navigator.language` si no hay valor guardado ni usuario con `locale`
- Selector: `LanguageSelector` (cabecera y perfil)
- Peticiones API: cabecera **`Accept-Language`** alineada con el idioma activo (`src/services/api.js`)
- Formatos: `src/i18n/format.js` (`formatFcfa`, `formatDate`, …)

## Kriol (`pov`) — revisión pendiente

La variante `pov` está redactada por el equipo de producto y **debe revisarse con un hablante nativo de Kriol de Guinea-Bissau**.

Claves especialmente dudosas (priorizar revisión):

- `errors.*` (tono formal vs coloquial)
- `notifications.ORDER_PICKED_UP.message`, `notifications.ORDER_COURIER_NEARBY.message`
- `receipt.header`, `receipt.products`
- Cualquier cadena en `src/i18n/locales/pov.json` bajo `delivery.*` y `landing.*`

En web, las claves ausentes en `pov.json` hacen fallback a `pt` y luego `es` (configuración i18next).

## Móvil (repo paralelo)

Reutilizar:

- Mismos códigos de idioma (`es`, `pt`, `pov`) y fallback.
- `PUT /api/auth/me` `{ locale }` + `Accept-Language` en API.
- Códigos de error `code` estables.
- Plantillas de notificación equivalentes (mismos nombres `template` / mismos `type`).
- Clave local `nha_kinhon_locale` recomendada para consistencia con web.
